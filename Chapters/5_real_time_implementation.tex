\chapter{Real Time Impelementation}

In this chapter the real time implementation of the trained networks will be described. The main focus will be on integrating the model into an environment where it can process the incoming data in real time and provide estimations with as little latency as possible. 

\section{Development Environment}

Before describing the development environment, the meaning behind real time implementation should be clarified. In this context, real time means that the model is able to process incoming data and provide estimations within a fixed time frame, which is determined by the system. Within every defined time step, the computational unit (eg. microcontroller) receives new input data at the beginning of the time step, processes it using the implemented model, and outputs the estimation before the next time step begins. It needs to be mentioned that the measurement data is not necessarily processed in the upcoming time step, there can be a delay of multiple time steps depending on the computational requirements of the model and the capabilities of the hardware.

A possible development environment for implementing an arbitrary control or estimation algorithm for vehicle application is the toolchain offered by dSpace \cite{dspace_tutorial} \cite{dspace_matlab} \cite{dspace_rt}. This toolchain allows the user to create models in MATLAB Simulink, generate C code from these models and utilize the generated code on the hardware developed by dSace, where it can be tested in real time. The hardware can be connected to a real vehicle via the CAN bus, or to a simulator for cost efficiency reasons. Even though the training of the AI models was done on real vehicle measurement data, for the real time implementation the latter option was chosen using the BeamNG.drive simulator \cite{beamng}. The main steps of the real time implementations are the following:
\begin{enumerate}
    \item Prepare the trained models in MATLAB using the Deep Learning Toolbox (DLT) \cite{matlab_dlt}.
    \item Integrate the trained models into MATLAB Simulink using DLT.
    \item Generating C code from the Simulink model using dSpace's ConfigurationDesk software \cite{dspace_configdesk}.
    \item Deploying the generated code on dSpace's MicroAutoBox \cite{dspace_microautobox} hardware using ControlDesk software.
    \item Connecting the MicroAutoBox to computer that runs BeamNG.drive via CAN bus.
    \item Testing the real time performance of the models with different step sizes.
\end{enumerate}

The main question to answer is what is the smallest step size that the MicroAutoBox requires to be able to run the model. In other words, how much time does the MicroAutoBox need to process the inserted model and provide estimation. This is crucial question since the smaller the step size, the more accurate and responsive the estimation will be, which can result better overall performance in a control application.  

\section{Results}

The chosen models for real time implementation were the best performing LSTM, GRU and the TCN architectures described in Chapter \ref{ch:direct_estimation}. Before starting the tests, a short calculation was made to estimate the MACs (Multiply-Accumulate operation) required by each model. This gives a rough idea about the computational requirements of the models, which can be compared to the capabilities of the MicroAutoBox hardware. The calculated MACs are the following \cite{mac_calculation}:

\begin{itemize}
    \item LSTM:
    \begin{equation}
        MAC_{LSTM} \approx L_{seq} \times  4(d_x \times d_h + d_h^2) \times {num of layers} = 15.667 \text{ M}
    \end{equation}
    \item GRU:
    \begin{equation}
        MAC_{GRU} \approx L_{seq} \times  3(d_x \times d_h + d_h^2) \times {num of layers} = 37.066 \text{ M}
    \end{equation}
    \item TCN:
    \begin{equation}
        MAC_{TCN} \approx L_{seq} \times \sum_{l=1}^{L} (k_l \times C_{in_l} \times C_{out_l}) \times B  = 5.888 \text{ M}
    \end{equation}
\end{itemize}

The results indicate that the TCN model has significantly lower computational cost compared to the recurrenet models which makes it even more desirable for real time applications.

After measuring these step sizes, it is clear that the TCN model is the most suitable for real time application due to its low computational cost and high accuracy. The main difference between the RNN based models is the sequence lenght which greatly affects computational costs. The LSTM model has a sequence length of 50 while the GRU model has a length of 90, which results in almost double the computational cost for the GRU model despite having only one layer more than the LSTM model.

A possible way to achieve smaller step sizes is to utilize the benefits of the created EKF based estimator, where the AI based direct estimator is used as a measurement function. This case offers a way to measurement update does not necessarily have to be performed at every time step, this the AI model can be run at lower frequencies while the prediction step of the EKF can be executed at every time step. This way the computational cost can be reduced while still having the benefits of the AI based model.
